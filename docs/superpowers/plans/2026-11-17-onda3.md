# Onda 3 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Emendas impositivas por vereador, página de promessas do prefeito e página "Resumo da semana" (com WhatsApp e RSS).

**Architecture:** Três módulos independentes em worktrees paralelos (Task 1 emendas: ferramenta de PDF + dados de referência; Task 2 promessas: ferramenta de PDF do TSE + dados de referência revisados à mão; Task 3 semana: regras puras + página + feed, sem integrar). Task 4 integra tudo (menu, cartões, robô, gerar-site).

**Tech Stack:** Node ≥22.13 ES modules, pdfjs-dist (já no projeto, ver `src/pdf.js` e `src/regras/linhas.js`), `node:zlib` para o zip do TSE (ver `src/ferramentas/campanha-2024.js`), HTML por template string, `node:assert`.

**Spec:** `docs/superpowers/specs/2026-11-17-onda3-design.md`

## Global Constraints

- Só dado oficial com link; fato, nunca acusação; nada de CPF nem nome de pessoa física fora vereadores e prefeito (nomes de entidades/associações com CNPJ podem aparecer; usar `limparNomeEmpresa` de `src/util/texto.js` se houver dígitos de CPF).
- Coleta educada (UA de `src/config.js`).
- Checagens só `node:assert` em `check/<modulo>.mjs`; sem framework, stubs ou rede.
- Tasks 1–3 só criam os arquivos listados nelas; não mexem em `package.json`, `src/coletar.js`, `src/atualizar.js`, `src/processar.js`, menu ou páginas existentes.
- `.md` como `.tmp` + renomear. Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Task 3: Resumo da semana (regras, página e feed)

**Files:** Create `src/regras/semana.js`, `src/site/semana.js`, `src/site/feed.js`, `check/semana.mjs`.

**Interfaces:**
- Consumes (formato de `dados.json` já existente; ler `data/processado/dados.json` para conhecer os campos): `proposituras` (`data`, `vereadores`, `grupo`, `locais`), `votacoes` (eventos com `data`, `resultado`, `contra`), `camara.respostas` / `respostas` com datas de resposta (ver `src/processar.js`), `receitas.ultimoMesOficial`, `gastos.anos[*].ultimoMes`, `prefeitura.obras.dataBase`.
- Produces:
  - `janelaSemana(hojeISO) -> { inicio, fim }` (7 dias terminando em `hoje`, datas AAAA-MM-DD).
  - `resumoSemana(dados, hojeISO, anterior = null) -> { inicio, fim, proposituras: { total, porVereador: [{ id, nome, total }], bairros: [{ nome, total }] (3) }, votacoes: [{ rotulo, data, resultado, contra: [nomes] }], respondidos: { total, porVereador }, novidades: [texto] }` — `novidades` compara com `anterior` (o resumo/meta da execução anterior, se houver) para "novo mês de receitas publicado", "nova folha da Câmara", "obra mudou de situação".

  - `paginaSemana(d) -> html` e `feedRss(d, url) -> xml` (um item com guid = início da semana, título "Resumo da semana de dd/mm a dd/mm", descrição curta, link `semana.html`).
